Google Sites embed codes

The hub is served from Vercel and read inside Google Sites. Every hub page needs a Google Sites page of its own at the hub domain, holding one full-page frame. This page prints those — frames, built from the same map the site itself uses, so the two cannot drift apart.

Building a page

  1. In the Google Sites Pages panel, press + and choose New full page embed. Paste the URL under each block below. A full page embed sizes itself to the page, so there is no block to drag and no height to guess at.
  2. The Name becomes the label in the Google Sites navigation bar, so give it the name a reader should see — Tutorials, not tutorials.
  3. Open Advanced and set the custom path to match the path shown above the block. The path has to match, or the hub’s own navigation will send readers to a page that does not exist.
  4. Publish, then open the Google Sites URL and click a link inside the frame. The browser address bar should move to another ailearninghub.law.stanford.edu page, not stay where it was.

If the address bar does not move. Google wraps an embed in a sandbox, and a sandbox that withholds top-level navigation will swallow those clicks: the frame changes but the address bar does not. That is the one thing worth testing before building all pages. If it happens, change LINK_TARGET in scripts/build-embed-map.py from "_top" to "_blank" and rebuild — links then open the right Google Sites page in a new tab instead.

The frames

Search stays inside the frame. Google Sites cannot pass a query string on its own URL through to the frame it hosts, so a Google Sites /search page would always come up empty. Search runs inside whichever frame the reader is already in, and its results link out to the right Google Sites page like any other hub link.
